Case Study — ESPNCricinfo

StatsGuru + CricGPT: From Filters to Conversation

Cricket knowledge is difficult to access. Fans know the score, but not the context. StatsGuru could close that gap — but it sat desktop-only, on a legacy stack, known to almost no one outside a small loyal base.

Why StatsGuru matters
  • — Core tool for pro cricket fans to generate stat tables
  • — Supports analysis, predictions, and fantasy strategy
  • — Built to ensure high usability and reliability for Cricinfo's most advanced users
The problem

A legacy tool that couldn't be found — or queried

Business problem

Cricinfo's richest data product reached only a sliver of its potential audience — usage skewed almost entirely to a small base of repeat, power users.

Root cause

Built for desktop on a legacy stack, StatsGuru's data wasn't built to be queried — only filtered and displayed. It couldn't utilize the depth of data Cricinfo actually had.

Band-aid

AskCricinfo worked around this by reading StatsGuru's HTML output directly rather than querying real data — a workaround that couldn't scale into a proper AI experience.

Strategy

Two phases. First, rebuild the foundation — new stack, mobile, better UX. Then, once the data was actually queryable, build a conversational layer on top.

1

Migrate to a new stack, with an API built for real data access

Reduced tech debt, made StatsGuru's data queryable for the first time — not just displayable.

Trade-off — slower and riskier than a surface redesign, but nothing downstream was possible without it.
2

Build for mobile, not just port the desktop UI

Reached the 80%+ of users who never touched StatsGuru because it lived on desktop only.

Trade-off — the dense filter UI power users relied on had to be redesigned, not resized.
3

Add search alongside filters

Type a player name instead of building a query from scratch.

Trade-off — needed to feel additive, not like a dilution of the tool's depth.
4

Advanced search, cross-vertical

One keyword search across teams, players, tournaments, matches — previously desktop-only, now on mobile too.

5

Overhaul filter-building for power users

Multi-team selection replacing one-at-a-time, simpler date-range selection, smoother query editing for those applying 10–20 filters.

Trade-off — depth for the loyal base couldn't be sacrificed while building for a broader audience.
6

Rework the results experience

Editable filters in place, flexible output types, adjustable results-per-page, better pagination, progressive disclosure.

7

Drive discovery, not just build it

A floating CTA and dedicated block added to the homepage.
